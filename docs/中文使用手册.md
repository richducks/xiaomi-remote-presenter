# 小米遥控器 2 Pro · Windows / macOS / Linux 跨平台使用手册

> 版本：2026-10-10。适用硬件：小米蓝牙语音遥控器 2 Pro / RC003，
> VID 0x2717，PID 0x32B8。
> 开源项目：[richducks/xiaomi-remote-presenter](https://github.com/richducks/xiaomi-remote-presenter)。
> **不需要增加硬件**：使用现有蓝牙遥控器和电脑软件。

## 2026-10-09 SAFE 固化与跨设备部署（优先阅读）

这是目前推荐部署的按键表，以**保持正常 Enter、避免卡键和意外窗口操作**
为第一目标。之前的 WPS/浏览器返回键功能保存在旧版完整映射方案中，
**不再默认启用**。

| 小米遥控器动作 | Linux SAFE | Windows SAFE | macOS SAFE |
| --- | --- | --- | --- |
| 小房子 | 仅浏览器 Ctrl+T | 仅浏览器 Ctrl+T | 仅浏览器 ⌘T |
| 菜单三横杠 | 仅浏览器 Ctrl+Tab | 仅浏览器 Ctrl+Tab | 仅浏览器 Control+Tab |
| TV | 仅浏览器 Ctrl+W | 仅浏览器 Ctrl+W | 仅浏览器 ⌘W |
| OK（普通界面） | 原样 Enter | 原样 Enter（已知视频网站标题除外） | 原样 Enter |
| OK（视频） | MPRIS/YouTube K | 网站标题匹配 F13 + 视频脚本 | 可选 F13 + 视频脚本，会占用浏览器 Enter |
| 圆盘上/下（视频） | Global Speed D/A，Firefox PiP 本地桥 | 网站标题匹配 D/A | 可选 D/A，占用浏览器上下方向键 |
| 返回、WPS、其他应用 | 原样 | 原样 | 原样 |

**已有 Linux 主机固化**：视频与三项标签页快捷键共用
`xiaomi-remote-video-only.service`（服务名沿用旧称），
登录后自动运行，旧 `xiaomi-remote-hid-filter.service` 不运行。
在本机运行 `bash linux/remote-mic/pin-linux-safe.sh --backup`，
会备份已部署代码、用户 systemd 服务快照及 SHA-256 到
`~/.local/state/xiaomi-remote-presenter/`。运行 `--verify` 对比当前
状态；如果后续改坏，明确运行 `--restore` 才恢复快照。个人设备路径、
蓝牙配对和私有运行数据都只保留在本机，**不会上传 GitHub**。

**新 Linux 设备**：执行 `bash linux/remote-mic/install.sh` 准备
依赖后，在 `linux/remote-mic` 执行
`bash install-services.sh --enable-video`，按系统配置所需 udev 权限与
Global Speed 插件；不自动开启旧版全功能映射。

**Windows 设备**：配对蓝牙，安装 AutoHotkey v2，进入 `windows`
目录运行 PowerShell `.\install.ps1 -InstallDriver`，
安装底层 Interception 需要管理员授权与系统重启；默认使用
`xiaomi_remote_safe.ahk`。可在已安装驱动后用
`.\install.ps1` 更新安全模式；原版本保存本地备份。
**仅在明确需求下使用 `-FullMode`。**

**Mac 设备**：配对蓝牙，安装 Karabiner-Elements，执行
`bash macos/install.sh` 后在其 UI 启用 SAFE 三条规则；
若已安装且希望自动激活，用
`bash macos/install.sh --enable-safe`（需要 Python 3）。
启用前会备份 Karabiner 配置，其他 Profile 保留。
**视频 OK 与倍速映射是单独的可选规则**，因为 macOS 无法仅靠
Karabiner 判断网页中是否有真实视频，不能保证与 Linux 无差别。

这三个系统使用相同的**安全默认原则**，但底层驱动、权限和对
HTML5 视频上下文的识别能力不同。Windows/macOS 目前只有配置与
静态/模拟测试，尚未用实体遥控器实机验证，不能称为无条件即插即用。
更详细步骤见 [Windows](../windows/README.md)、
[macOS](../macos/README.md) 和 [Linux](../linux/remote-mic/README.md)。

### 2026-10-10 Ubuntu 浏览器与夸克视频恢复

本机已确认 SAFE 服务正常启用，浏览器 Ctrl+T、Ctrl+Tab、Ctrl+W 可由同等虚拟 HID 事件触发；服务从早晨持续运行后曾记录 AT-SPI 无障碍总线连接错误，重启服务可重新抓取遥控器。用户随后反馈浏览器控制和视频观看已恢复，但未做夸克跨集播放完整自动化验收。Firefox 当前使用 `media.autoplay.default=0` 和 `media.block-autoplay-until-in-foreground=false`；两项**允许播放**，但无法替代夸克网站的连续播放/下一集设置。

完整的逐项诊断、非破坏性 systemd 重启命令，以及供新机器**主动选择**的 Firefox `user.js` 设置工具，见 [Linux 增强版恢复记录](../linux/remote-mic/README.md#2026-10-10firefox--夸克网盘连播与浏览器按键恢复记录)。默认检查不修改配置；只有明确执行 `python3 linux/remote-mic/firefox-autoplay.py --apply` 才会开启 Firefox 的**全站点自动播放**，原 `user.js` 在本机备份。SAFE 保留 WPS 原生按键，并**不**提供旧模式的 OK→F5 / 返回→Esc，勿同时启动两个 HID 服务。

## 一、设计目标

把遥控器作为日常浏览网页、视频和演示文稿的输入设备，遵循三条原则：

1. **仅拦截指定蓝牙遥控器**，不更改笔记本/外接键盘；
2. **按使用环境变换功能**：浏览器负责标签页、导航和视频，
   WPS/PowerPoint/Keynote 负责幻灯片，其他程序尽可能原样透传；
3. **单次按键只执行一次**，避免长按连续关闭网页、打开多个标签页；
   音量键仍然原样控制电脑音量。

不同系统需要不同的输入拦截后端，不能直接把 Ubuntu 的 evdev 服务
复制到 Windows 或 macOS：

- Linux：evdev + uinput + GNOME/AT-SPI 前台应用检测；
- Windows：AutoHotkey v2 + AutoHotInterception（设备级驱动）；
- macOS：Karabiner-Elements 的设备匹配与前台应用条件。

**功能映射已经编码到三个系统，但只有 Ubuntu 真机经过实际输入验收。**
其他两套已做好安装文件、配置和自动化检查，仍需在对应系统配对遥控器、
根据实体按键事件进行测试。本文严格区分这两种状态。

## 二、遥控器按键总表

下表中「浏览器」指独立 Firefox、Chrome/Chromium、Edge、Brave、
Opera、Vivaldi 等受支持程序。macOS 同时适配 Safari。

| 遥控器按钮 | 操作目的 | Windows / Linux | macOS |
|---|---|---|---|
| 小房子 Home | **新增标签页** | Ctrl + T | Command + T（⌘T） |
| TV | **关闭当前标签页** | Ctrl + W | Command + W（⌘W） |
| 三条横杠 ≡（菜单） | **切换到右侧标签页** | Ctrl + Tab | Control + Tab（⌃Tab） |
| 返回 Back | **后退一页** | Alt + ← | Command + [（⌘[） |
| OK（浏览器有视频） | **播放／暂停** | Linux：MPRIS→YouTube K；Windows：F13+用户脚本 | F13+用户脚本 |
| 圆盘上 | **视频加速 0.1x** | Global Speed 的 D | Global Speed 的 D，需启用可选视频模式 |
| 圆盘下 | **视频减速 0.1x** | Global Speed 的 A | Global Speed 的 A，需启用可选视频模式 |
| 音量 + / − | **调整音量** | 保持原样 | 保持原样 |

### 为什么「返回」不再等于新建标签页？

原先返回键与小房子键同为 Ctrl+T，功能重复，用户容易误操作。
现在把「返回键」调整为符合直觉的**返回上一页**；
如果要新建页面按小房子，如果要关闭按 TV，如果要换页面按菜单。
无需记住多个实体键共用一个功能。

### 演示文稿模式

| 遥控器 | Linux WPS 演示 | Windows WPS/PowerPoint/Impress | Mac WPS/PowerPoint/Keynote |
|---|---|---|---|
| OK | F5，从头放映 | F5，从头放映 | WPS F5；PPT ⌘⇧Return；Keynote ⌘⌥P |
| 返回 | Esc，退出放映 | Esc，退出放映 | Esc，退出放映 |
| 其余浏览器专属按钮 | 原样透传 | 原样透传 | 原样透传 |

物理遥控器本来可能发出的 F5 被**该设备专属地拦截**，
防止意外刷新浏览器；演示场景中的 F5 是软件专门生成的。
键盘自己的 F5 不受影响。

### 按键电气与 HID 识别

| 实体按钮 | Linux 输入事件 | Windows 默认 AHK 热键 | macOS Karabiner 默认事件 |
|---|---|---|---|
| 小房子 | KEY_HOME / KEY_WWW | Home / Browser_Home | home / ac_home |
| TV | KEY_GRAVE，HID Usage 0x35 | SC029 | grave_accent_and_tilde |
| 三横杠 | KEY_COMPOSE，HID Usage 0x65 | AppsKey | application |
| 返回 | KEY_BACK | Browser_Back | ac_back |
| OK | KEY_ENTER / KEY_OK | Enter | return_or_enter |
| 上/下 | KEY_UP / KEY_DOWN | Up / Down | up_arrow / down_arrow |

**HID 事件在不同固件和系统驱动下可能不同。** 例如 TV 对应的
KEY_GRAVE 不是普通意义的键盘字符，而是这款遥控器的设备专属映射。
Windows 使用 Monitor.ahk、Mac 使用 Karabiner-EventViewer，
确认实际报告的按键码后调整规则，不应盲目修改整个系统的键盘设置。

## 三、Windows 安装说明

### 3.1 必需软件

- AutoHotkey v2；
- AutoHotInterception + Interception 底层驱动（安装脚本提供下载）；
- 浏览器视频 OK：Tampermonkey 或 Violentmonkey；
- 视频倍速：Global Speed 浏览器扩展。

系统建议 Windows 10/11。此方案只拦截指定 VID/PID 的设备。

### 3.2 实施步骤

1. 在 Windows 蓝牙设置中连接小米遥控器。
2. 安装 AutoHotkey v2（不能误装旧的 v1）。
3. 下载本仓库，右击 windows 文件夹 → 在终端打开 PowerShell。
4. 执行：

        Set-ExecutionPolicy -Scope Process Bypass
        .\install.ps1 -InstallDriver

5. 批准驱动安装，**重启 Windows**。
6. 通过系统启动项启动脚本，验证浏览器 Home 新建、TV 关闭、
   菜单切换、返回后退。
7. 在浏览器中启用 Tampermonkey/Violentmonkey，并导入
   [通用浏览器视频脚本](../browser/xiaomi-remote-video.user.js)。
   安装脚本同时会将它复制到：

        %LOCALAPPDATA%\XiaomiRemotePresenter\browser\xiaomi-remote-video.user.js

8. 在 Global Speed 设置中配置页面快捷键 D=+0.1x、A=-0.1x，
   确认允许在 YouTube、Bilibili、抖音、夸克等网站生效。

**Windows 上、下方向键只在识别到常见视频站点标题时改为 D/A**，
普通网页仍保留导航；这种标题识别是启发式的，不保证识别所有站点，
更不能当作「已经检测到真实视频正在播放」。

**风险提示：** Interception 是系统底层键盘拦截驱动。
第一次安装前准备备用键盘和本地恢复方式，尤其不要在只有远程连接
的生产电脑上盲目安装。

### 3.3 卸载与升级

- 升级：更新仓库文件，重新执行安装脚本；已复制到安装目录的配置才会更新。
- 卸载：执行 windows/uninstall.ps1 删除用户程序和启动项；
  驱动不会随用户目录自动删除，需按 Interception 官方方式卸载并重启。
- TV / MENU 不响应时：运行 AutoHotInterception 附带的 Monitor.ahk，
  核实实际键码、设备实例编号和 HID 类型。

## 四、macOS 安装说明

### 4.1 安装

1. 蓝牙配对遥控器，安装 Karabiner-Elements；
   授予需要的 Input Monitoring（输入监控）与 Accessibility（辅助功能）权限。
2. 下载仓库，在 macos 目录执行：

        ./install.sh

3. Karabiner-Elements → Complex Modifications → Add predefined rule。
4. 启用名称包含「Xiaomi Remote 2 Pro · 浏览器 / 演示」的**核心规则**。
5. 将 [通用浏览器视频脚本](../browser/xiaomi-remote-video.user.js)
   导入 Tampermonkey/Violentmonkey，使 OK/F13 真正播放与暂停视频。
6. 在浏览器安装 Global Speed，并按后续章节决定是否启用倍速模式。

### 4.2 macOS 快捷键与 Windows 的区别

macOS 中大多数浏览器的「新建」「关闭」使用 Command（⌘），而非 Ctrl；
返回上一页使用 Command + [。因此规则在 Mac 上发送的是
**⌘T、⌘W、⌘[、⌃Tab**，不是机械复制 Windows 快捷键。

macOS 后端设备匹配条件为 Vendor 10007、Product 12984；
每条浏览器规则还要求浏览器位于前台。Karabiner JSON 采用
repeat=false，避免一次长按产生重复快捷键。

### 4.3 视频倍速为什么是可选的？

Mac 的 Karabiner 目前仅靠「浏览器进程在前台」不能可靠得知
网页是否真的在播放视频；所以默认**不覆盖上下方向键**。

如果经常看长视频，需要遥控器圆盘上/下控制 Global Speed：

1. 在 Global Speed 配置 D 和 A 页面快捷键；
2. 在 Karabiner 中另外启用规则
   「Xiaomi 2 Pro · Global Speed 视频模式（可选，浏览器占用方向键）」；
3. 进入视频网站验证每次上/下改变 0.1x；
4. **代价：浏览器的所有网页中，上/下会改为发送 D/A，
   不能再正常滚动页面。** 需要滚动时禁用这两个可选规则。

这不是与 Linux 完全一致的视频上下文识别，本文明确保留此差异。
Safari 对 Global Speed 的实际兼容程度也需按所使用的扩展验证。

### 4.4 Mac 设备识别与卸载

Karabiner-EventViewer 的 Devices、Events、Frontmost Application 页面
用于确认蓝牙 HID 报告的实际 TV、Home、Menu、Back 编码，以及
浏览器应用的 Bundle Identifier。若不一致，以实测事件修改 JSON。

卸载时在 Complex Modifications 关闭本项目规则，再删除
用户目录下 assets/complex_modifications 中对应的两个 Xiaomi JSON。
本项目不会修改普通键盘规则。

## 五、Ubuntu / Linux 安装说明

Linux 已在 Ubuntu 26 + GNOME Wayland + Firefox 实机部署，
与 Windows/Mac 不使用同一套后端。

1. 蓝牙配对遥控器。
2. 按 [Linux 增强版指南](../linux/remote-mic/README.md)
   安装 Python、evdev/uinput、设备权限和用户 systemd 服务。
3. 默认 SAFE 模式检查服务（旧全功能服务必须不运行）：

        systemctl --user is-active xiaomi-remote-video-only.service   # active
        systemctl --user is-active xiaomi-chatgpt-web-bridge.service  # active
        systemctl --user is-active xiaomi-remote-hid-filter.service   # inactive
        systemctl --user is-active xiaomi-remote-wps-linux.service    # inactive

4. Firefox/Chrome 安装 Global Speed；视频上/下直接映射其 D/A 热键，
   需保证 URL 白名单包含目标网站。YouTube OK 优先使用匹配的
   MPRIS 媒体会话，失配时使用页面原生 K 键。
5. SAFE 保留 WPS 和返回的原始行为；只有停用 SAFE 后切到旧完整映射，
   才能使用 WPS OK→F5 / 返回→Esc 和浏览器返回 Alt+左箭头。

Linux 额外包括已测试的 Firefox 原生 PiP Global Speed 桥接、
蓝牙语音输入及本地 ChatGPT 网页连接组件；它们仍属于
**Linux 专有增强**，不是 Windows/macOS 的已交付功能。

## 六、浏览器 OK：为什么需要通用视频脚本？

Windows 与 Mac 的浏览器 OK 经设备级重映射后会发送 F13，
由 Tampermonkey/Violentmonkey 的通用脚本监听该按键。
它会定位当前网页**可见的 HTML5 video**，调用 play()/pause()。

安全与兼容边界：

- 只在浏览器所在的设备级规则范围内处理遥控器 OK；
- 普通 F13 并不会修改系统全局媒体播放；
- 用户正在搜索框、评论框或其他可编辑区域输入时不响应；
- 长按不会连续播放/暂停；
- **不修改 playbackRate**，倍速只能由单独安装的 Global Speed 负责；
- 浏览器阻止自动播放、视频网站的专有播放器/DRM 或跨域 iframe
  可能限制功能，需要在目标页面实测；Linux 原版使用的是
  MPRIS/YouTube K 后备逻辑，不依赖本脚本。

建议先测试 YouTube，再测试 Bilibili、抖音、夸克；分别验证
播放、暂停、退出全屏、标签切换后正确控制当前页面。

## 八、常见问题与排查

**Q1：TV、返回、菜单键在新系统不工作？**

检查对应系统的实体 HID 按键码。遥控器可能以键盘事件或
消费控制键报告同一实体按钮；不应把对普通键盘生效的全局映射
当作设备专属配置。

**Q2：为什么 YouTube OK 没反应？**

Windows/macOS 必须先安装用户脚本，确认 F13 能到达网页；
搜索框仍然聚焦时，脚本会主动忽略该按键。Linux 检查当前
视频媒体会话、页面焦点以及浏览器是否真在前台。

**Q3：为什么某个视频不能变速？**

检查 Global Speed 已安装、D/A 快捷键配置正确、站点 URL 已
加入白名单；Windows 的视频网站标题识别也可能未命中；
Mac 需要手动开启可选方向键规则。不要给视频叠加第二个
独立倍速引擎，以免与 Global Speed 相互覆盖。

**Q4：Linux Firefox 画中画能用，Mac/Windows 也保证能用吗？**

不能。Linux 有专门的浏览器脚本与桥接服务；Mac/Windows
虽然新增了独立的视频 OK 控制，但原生 PiP 以及受保护视频仍需
在目标平台逐项验收。

**Q5：为什么 Windows 需要重启，而 Ubuntu 无需每次重启？**

Windows 使用 Interception 系统驱动，安装后需要重新加载。
Ubuntu 的 evdev/uinput 使用用户 systemd 服务即可重启。
